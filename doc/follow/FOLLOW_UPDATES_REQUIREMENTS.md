# 追更与内容更新提醒需求

> 状态：开发中。第一阶段已启动，本文档同时作为实现与验收依据。

## 1. 背景

Jive 当前支持将影片收藏到本机，但收藏仅用于保存内容，不能主动判断连续剧、动漫或综艺是否发布了新集。用户重新进入 App 后，需要逐个打开详情页才能知道内容是否更新。

本功能希望让用户订阅正在更新的内容。App 再次进入前台后自动检查追更内容是否有新集，通过轻量提醒帮助用户快速找到更新内容。

## 2. 产品目标

1. 用户可以在详情页对连续剧、动漫和综艺执行追更。
2. App 冷启动或重新进入前台后，可以自动检查追更内容是否更新。
3. 有更新时，通过底部导航提醒和追更列表内的卡片状态通知用户。
4. 用户能够看到当前最新集、相对上次确认新增的集数，并快速进入详情页。
5. 保留现有收藏能力，不把电影收藏强行解释为追更。

## 3. 核心概念

收藏和追更是两个独立的用户状态，但共享同一条内容身份和内容快照：

- **收藏**：将内容保存到个人内容库，不检查新集。
- **追更**：将内容保存到个人内容库，并开启更新检查。
- **停止追更并保留收藏**：关闭更新检查，内容仍保留在收藏中。
- **从个人内容库移除**：同时清除收藏和追更状态。

追更包含收藏语义：

```text
追更 = 保存到个人内容库 + 开启更新检查
收藏 = 只保存内容，不检查更新
```

底层应以 `globalId = sourceId:sourceVideoId` 作为统一内容身份，避免收藏和追更分别保存两份可能失去同步的影片快照。

## 4. 详情页交互

### 4.1 单一动态关系按钮

详情页不同时展示“收藏”和“追更”两个按钮，而是根据内容类型和当前状态显示一个动态按钮：

| 内容与用户状态 | 按钮文案 |
| --- | --- |
| 连载电视剧、动漫或综艺，尚未追更 | `＋追更⌄` |
| 已追更 | `✓ 已追更` |
| 电影、单集内容或明确完结内容，尚未收藏 | `♡ 收藏` |
| 已收藏且未追更 | `♥ 已收藏`；若内容支持追更，应提供开启追更的可发现入口 |

点击连载内容的 `＋追更⌄` 后，在按钮下方打开锚点下拉菜单，不使用底部弹窗：

```text
🔔 追更并收藏
   有新集时提醒

♡  仅收藏
   保存但不提醒
```

点击菜单外部即可取消。按钮上的下拉箭头用于提示这里不止一个动作；菜单通过“追更并收藏”明确说明追更自动包含收藏。

选择“开启追更”后完成保存和开启更新检查，并给予轻量反馈：

```text
已加入追更，有新集时会提醒你
```

点击 `✓ 已追更` 时不应立即删除记录，而是提供以下选择：

```text
停止追更？

停止提醒，保留收藏
从个人内容库移除
取消
```

### 4.2 下载入口与选集弹窗

详情页右上角原“下载管理”入口改为当前内容的下载按钮，播放区域只保留播放和动态关系按钮：

```text
[ ▶ 播放第 12 集              ]  [ ＋追更 ]
```

已追更时：

```text
[ ▶ 继续播放                  ]  [ ✓ 已追更 ]
```

电影或单集内容：

```text
[ ▶ 立即播放                  ]  [ ♡ 收藏 ]
```

布局规则：

- 播放按钮为主要按钮，自适应占据剩余宽度。
- 下载按钮位于 AppBar 右侧，点击后打开当前内容的选集下载弹窗。
- 动态关系按钮保留图标和文字，建议宽度约 `84～96px`。
- 按钮之间建议保留 `8px` 间距。
- 窄屏可以缩短播放文案，但应优先保留“追更/已追更/收藏”文字，避免仅用铃铛图标造成歧义。

选集下载弹窗底部使用并行操作：左侧“下载管理”进入任务页面，右侧“确认下载”提交本次选集。剧集勾选框使用圆角样式；已经加入下载且未取消的剧集保持勾选并置灰，点击时提示“已经添加到下载”，不重复创建任务。“全选”和确认数量只统计尚未添加的剧集。

### 4.3 跳过片头、片尾设置收起

当前详情页分别展示“跳过片头”和“跳过片尾”标题，并为每一项常驻展示“关闭 / 30 秒 / 60 秒 / 90 秒 / 自定义”整组选择芯片，占用空间较大。

后续将其收起为同一行的两个等宽状态选择按钮，不再常驻展示选项：

```text
[ 片头 · 关闭 ⌄ ]    [ 片尾 · 关闭 ⌄ ]
```

设置时长后直接显示当前状态：

```text
[ 片头 · 90秒 ⌄ ]    [ 片尾 · 60秒 ⌄ ]
```

布局与视觉规则：

- 两个按钮等宽排列，高度约 `44～48px`；
- 默认使用低强调度的描边样式，不与播放主按钮争夺视觉焦点；
- `关闭` 使用次要文字色，已开启的时长使用主题强调色；
- 不再额外展示“跳过片头”“跳过片尾”两行标题；
- 极窄屏可以去掉分隔圆点，显示为 `片头 关闭 ⌄` 和 `片尾 关闭 ⌄`，但仍保持同行；
- 平板或横屏继续同行展示，不恢复为常驻芯片；
- 详情页与竖屏播放器下方信息面板继续复用同一套设置组件和持久化状态。

点击任一按钮后，在对应按钮下方打开圆角锚点下拉菜单。菜单中心优先与按钮中心对齐，靠近屏幕边缘时在安全区内自动避让，并使用短距离下滑加淡入动画。以片头为例：

```text
跳过片头

○ 关闭
○ 30 秒
○ 60 秒
● 90 秒
○ 自定义

说明：播放开始时自动跳过前 90 秒
```

片尾下拉菜单使用相同选项，并将说明调整为例如 `剩余 60 秒时自动结束或播放下一集`。追更、片头和片尾复用相同的圆角、阴影、定位和动画样式。

选择“关闭、30 秒、60 秒、90 秒”时应：

1. 立即保存当前影片的对应设置；
2. 自动关闭下拉菜单，不要求再次点击确定；
3. 同步刷新收起按钮上的状态；
4. 使用轻量提示反馈，例如 `已设置跳过片头 90 秒`。

选择“自定义”时，在当前下拉菜单内切换为数字输入，不继续叠加对话框：

```text
自定义片头时长

[ 120 ] 秒
请输入 1～600 秒

[ 取消 ]                  [ 保存 ]
```

自定义值仍沿用当前 `1～600` 秒的有效范围。输入无效时留在下拉菜单内显示错误，不修改原设置；保存成功后关闭菜单并显示新的时长。

TV 端沿用相同的信息结构和锚点菜单；两个收起按钮均须可独立聚焦，按确认键打开菜单。

## 5. 提醒入口与追更页面

“我的”页使用三个独立 Tab：`追更 / 收藏 / 最近观看`。

- “追更”只展示已开启更新检查的内容；
- “收藏”只展示已收藏但未追更的内容；
- 追更自动包含收藏，但同一内容只出现在“追更”Tab，不在“收藏”Tab 重复展示；
- 停止追更并保留收藏后，内容从“追更”移动到“收藏”；
- 电影只提供收藏关系，不提供追更入口。

### 5.1 追更更新提醒

底部导航继续保持“首页 / 搜索 / 我的”，不新增第四个主 Tab。

当存在尚未查看的内容更新时：

- “我的”底部导航项只显示红点，表示是否存在未读追更更新；
- “追更” Tab 右上角显示有更新的影片数量，最大显示 `99+`；
- 追更列表中有更新的内容置顶；
- 内容卡片的封面底部以半透明渐变条显示当前最新集，例如 `更新至 第12集`；
- 未读更新在封面右上角显示新增集数角标，例如 `新增2集`；已读后仅移除角标，保留最新集信息；
- 未读角标使用红底白字和浅色细描边，轮廓为右上角与左下角同向斜切的平行四边形；角标贴合封面右上区域，右侧边界不超出封面，并与黄色品牌强调色区分；
- 未读状态属于内容而不是页面：首页和搜索结果中出现同一 `globalId`时也显示 `新增N集`，但不额外显示封面底部最新集条；不按标题跨来源匹配；
- 检查失败和来源异常继续在封面下方的副标题显示，不占用右上角角标；
- 可以在首次发现更新时显示一次轻量横幅，例如 `你追的 3 部内容更新了`；
- 默认不使用每次启动都出现的强提醒弹窗。

“检测到更新”和“用户已查看更新”必须是两个不同状态。进入“我的”页面不应直接清除所有红点；用户打开对应内容或主动执行“全部标为已读”后，才清除相应未读状态。

### 5.2 下载入口状态动画

“我的”页现有下载快捷入口保持原尺寸、标题、副标题和点击行为，只优化左侧约 `20～24px` 的下载图标区域。有活动下载任务时，通过“真实进度环 + 低频箭头下落”表达正在下载，不让整个快捷入口卡片持续闪烁或缩放。

推荐效果：

```text
┌──────────────────────┐
│  ◔↓   下载           │
│       2 个下载中 · 46%│
└──────────────────────┘
```

- 外层细圆形进度环显示活动任务的整体进度；
- 中间下载箭头每隔约 `1.5` 秒向下移动 `2～3px`，完成一次后停顿，不连续快速跳动；
- 进度环更新使用约 `200～300ms` 的平滑过渡；
- 使用主题强调色，但不持续改变整个快捷入口的背景；
- 已有的“任务数量 + 整体进度百分比”副标题继续保留。

各下载状态的图标表现：

| 下载状态 | 图标表现 | 是否持续动画 |
| --- | --- | --- |
| 无下载任务 | 普通下载图标 | 否 |
| `queued` 等待下载 | 缓慢淡入淡出或呼吸 | 是，使用弱动画 |
| `downloading` 正在下载 | 进度环推进，箭头低频下落 | 是 |
| `paused` 全部暂停 | 下载图标附加小型暂停标记 | 否 |
| `failed` 存在失败 | 下载图标附加警告点 | 否 |
| `completed` 全部完成 | 静态已下载图标 | 否 |

当多种任务状态同时存在时，视觉表达优先级为：

```text
失败 > 正在下载 > 排队 > 暂停 > 已完成 > 无任务
```

如果存在失败任务，同时仍有其他任务正在下载，应保留下载动画，并在图标角落附加小型警告点，不使用失败状态完全覆盖正在下载状态。

单个或一批任务刚完成时播放一次短反馈：

1. 进度环完成一整圈；
2. 下载箭头切换为对勾；
3. 对勾轻微放大后恢复；
4. 动画总时长约 `600～800ms`；
5. 若没有其他活动任务，之后停留为静态已下载图标；若仍有活动任务，则恢复下载动画。

动画约束：

- 不让整个下载卡片持续闪烁、晃动或缩放；
- 不使用持续快速旋转的下载图标；
- 不因每一次细小进度变化触发弹跳；
- 页面不可见时停止装饰性循环动画，避免无意义消耗；
- 系统开启“减少动态效果”时，停止箭头位移和呼吸动画，仅保留静态进度环、状态标记与文字进度；
- 动画不改变下载入口的点击区域和无障碍语义。

## 6. 更新检查规则

第一阶段只实现 App 进程内的前台检查，不要求 App 被系统终止后继续定时运行，也不要求系统通知栏推送。

建议检查时机：

- App 冷启动并完成首帧后检查一次；
- App 从后台恢复到前台且超过检查间隔时再次检查；
- 用户在追更页面主动下拉时强制检查。

执行要求：

- 只检查已开启追更的内容，不检查普通收藏和电影收藏；
- 按 `sourceId` 分组，并限制请求并发数，避免大量详情请求同时发出；
- 自动检查必须绕过短时详情缓存，获取上游最新详情；
- 单条内容检查失败不能导致整批失败；
- 检查失败时保留上次成功结果，不得清除追更或判定为“没有更新”；
- 内容绑定的原来源不可用时，显示来源异常状态，不自动迁移到其他来源。

## 7. 更新判断

第一阶段的“新集提醒”只比较剧集数量：远端剧集数大于用户已确认的剧集数时，提醒新增的差值。同数量改名、替换、重排或剧集数减少都不产生新集提醒。

剧集数减少时不下调已确认数量，避免上游临时返回缩短列表、恢复后误报 `新增N集`。`Video.remarks` 不参与更新判断。

每次成功获取的剧集列表仍生成稳定版本签名，仅用于保存远端版本、刷新快照和后续诊断，不用于触发新集提醒。签名匹配优先级为：

1. `Episode.identity`；
2. 解析后的规范化集数；
3. 规范化剧集名称；
4. 列表顺序作为最终回退。

第一版展示使用剧集总数和最新一集名称，底层保留剧集版本签名，以便后续诊断：

- 上游新增剧集；
- 特别篇或非数字剧集插入；
- 剧集名称或内容发生替换；
- 上游错误地缩短或重排列表。

至少需要区分以下版本状态：

- 上次用户已确认的版本；
- 本次远端检查到的版本；
- 已经产生过提醒的版本；
- 用户已经查看过提醒的版本。

## 8. 数据兼容原则

现有 `FavoriteRecord` 只保存不含剧集列表的 `Video` 快照，其 `updatedAt` 也是本地记录更新时间，不能直接作为追更基线。

后续实现应满足：

- 旧的 `favorite_videos_v1` 数据继续可用；
- 旧收藏迁移后默认为“已收藏、未追更”，不能自动开启追更；
- 收藏状态和追更状态共享内容身份，但分别记录状态与时间；
- 追更记录保存检查时间、剧集版本、最新集显示文本和未读状态；
- 数据迁移失败不得清空旧收藏。

## 9. 第一阶段范围

### 包含

- 收藏数据的向后兼容升级；
- 详情页动态“收藏/追更”按钮；
- 播放、下载、动态关系按钮保持同行；
- 连载内容的本地追更状态；
- 启动、恢复前台和手动触发的更新检查；
- “我的”导航红点或数量；
- 追更列表更新置顶与卡片最新集信息；
- 单项已读和全部标为已读；
- 检查失败及来源不可用状态。

### 不包含

- App 被系统终止后的后台定时检查；
- Android/iOS 系统通知栏推送；
- 账号、云同步和跨设备追更；
- 服务端统一轮询内容源；
- 未经用户确认自动迁移追更来源；
- 自动下载新集。

## 10. 待实施前细化

以下参数和规则在进入开发前继续确认：

- 如何可靠判断内容属于电影、连载、综艺、动漫或已完结；
- App 从后台恢复后的默认检查间隔；
- 单次最大检查数量、并发数和超时时间；
- 红点显示纯状态还是未读更新数量；
- 已收藏但未追更的连载内容，开启追更入口具体放置位置；
- 打开详情页、开始播放或手动操作中的哪一步视为“已查看更新”。

## 11. 初步验收标准

1. 连载内容详情页显示 `＋追更`，电影或单集内容显示 `♡ 收藏`。
2. 点击追更后，App 重启仍保留追更状态。
3. 下载按钮位于详情页右上角；播放和动态关系按钮在手机详情页保持同一行且不溢出。
4. 上游新增剧集后，下一次有效检查能够产生未读更新。
5. “我的”入口出现提醒，追更卡片显示最新集和新增集数。
6. 仅进入“我的”页不会错误清除全部未读更新。
7. 同一远端版本不会在每次启动时重复产生新的提醒。
8. 单个来源超时或失败不会清除已有追更结果，也不会阻塞其他内容检查。
9. 旧收藏升级后仍存在，且不会被自动设置为追更。
10. 停止追更时可以选择保留收藏或从个人内容库完全移除。
11. 片头和片尾设置在详情页及竖屏播放器信息面板中均收起为同一行的两个状态按钮。
12. 收起按钮正确显示 `关闭`、预设时长或自定义时长，页面重进后状态保持一致。
13. 点击片头或片尾按钮能打开对应圆角锚点下拉菜单，选择预设后立即保存、关闭并刷新状态。
14. 自定义时长在同一下拉菜单内完成输入和校验，不叠加第二层对话框。
15. 窄屏下两个收起按钮保持同行且不发生文字或布局溢出；TV 端可以通过遥控器完整操作。
