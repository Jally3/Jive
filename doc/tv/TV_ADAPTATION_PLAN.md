# 最小 TV 适配需求方案（Android TV / 索尼）

状态：**开发中**。目标分支 `feature/tv-adaptation`。FR-1～FR-4 已实现（leanback 入口、焦点体系、遥控器按键映射、横屏收敛），待真机实测（P0 侧载验证与 P3 打磨）。投屏为另一条独立路线，见 [`../cast/CAST_PLAN.md`](../cast/CAST_PLAN.md)，两者不冲突。

## 1. 背景与目标

把现有手机 App 直接安装到索尼 Android TV（侧载 APK），用遥控器完成看片核心链路。播放链路（ExoPlayer / 本地代理 / 广告过滤 / Syncnext 插件）已确认平台无关，零改动即可在电视上运行；差距集中在**横屏布局与遥控器（D-pad）交互**。

本方案只做"最小适配"：让核心链路用遥控器走得通，不追求 leanback 风格的原生 TV 体验。

## 2. 目标与非目标

### 目标（In Scope）

- 电视桌面可见、可启动（leanback 入口与横幅图标）。
- 遥控器完成核心链路：**浏览首页 → 打开详情 → 选集 → 播放 → 播放控制（暂停/进度/上下集）→ 返回**。
- 全程横屏，关键交互组件（卡片、按钮、剧集 chip、Tab）可聚焦且有明显焦点态。
- 搜索可用（电视软键盘输入）。
- 不破坏手机端现有交互与 UI。

### 非目标（Out of Scope）

- leanback 风格完整重构（大卡片横排、焦点放大动画等）。
- 触屏手势的电视替代精细化（双击暂停、滑动亮度音量等）。
- 下载/缓存管理页的遥控器优化（电视存储有限，保留入口但不优化）。
- Google Play TV 商店上架。
- 投屏能力（见 cast 方案）。

## 3. 功能需求

### FR-1 安装与启动

- Manifest 增加 `android.intent.category.LEANBACK_LAUNCHER`（与现有 `LAUNCHER` 并存，手机端不受影响）。
- 声明 `android.hardware.touchscreen` 为 `required=false`；`android.software.leanback` 声明为 `required=false`（同一 APK 同时支持手机与电视）。
- 提供 TV 横幅图标 `android:banner`（320×180 xhdpi drawable）。
- 电视端强制横屏（手机端保持现状；可通过 `uiMode` 判断或 leanback 兼容方式实现）。

### FR-2 焦点体系基座

- 全局焦点态样式：聚焦时高亮描边/底色变化（跟随「夜幕影院」设计规范，焦点色用 accent）。
- 盘点并补齐关键组件的焦点能力：`VideoCard`、详情页播放/收藏/下载按钮、剧集 `ChoiceChip`、来源 Tab、`SourceSelectorSheet` 列表项、底部导航。
- `GestureDetector` 独占的交互点（卡片点击、海报点击等）补 `Focus`/`FocusableActionDetector` 或改为 `InkWell`。
- 页面初始焦点合理（进入详情默认聚焦"播放"按钮；弹层打开时焦点进弹层）。

### FR-3 播放页遥控器映射

| 遥控器按键 | 行为 |
| --- | --- |
| OK / 确定 | 播放/暂停；控制条隐藏时先唤出控制条 |
| 左 / 右 | 快退/快进 10 秒（控制条显示时移动焦点或步进进度） |
| 上 / 下 | 唤出控制条 / 收起控制条 |
| 返回 | 控制条显示时先收起，否则退出播放页 |
| 菜单键（如有） | 打开选集/倍速面板 |

- 触控手势层在 TV 上不生效（不删代码，焦点模式下遥控器事件不走手势）。
- 选集面板可用 D-pad 在剧集间移动焦点并 OK 确认。

### FR-4 横屏布局

- 首页/搜索：网格在横屏下列数自适应放大（`VideoGrid` 已有自适应，确认电视宽度下表现）。
- 详情页：横屏下封面与信息横向排布，避免竖屏单列拉长。
- 弹层（来源选择、选集）横屏下宽度收敛居中，不全屏拉宽。

## 4. 非功能需求

- 同一 APK 兼容手机与电视，不引入 TV 专属构建变体。
- 电视性能：封面图加载与列表滚动在索尼电视芯片（MediaTek）上不卡顿；播放器走硬件解码。
- 已知风险点 `screen_brightness` 在电视上调用可能抛异常：确保 TV 路径不会触发（仅手势层调用），并做防御性容错。

## 5. 技术要点

- 焦点：Flutter `Focus` / `FocusTraversalGroup` / `FocusableActionDetector`；遥控器按键经 `Shortcuts`/`Actions` 或 `KeyEvent`（`LogicalKeyboardKey.select`、`enter`、方向键、媒体键）映射。
- 不引入运行时"TV 模式开关"做两套 UI：交互同时兼容触摸与焦点（焦点样式在手机端不可见），仅布局按横屏自适应。
- 构建与安装：`flutter build apk --release`（默认含 ARM ABI）→ 电视开开发者选项与网络 adb → `adb connect <电视IP>` → `adb install`。
- 测试：焦点逻辑与遥控器按键映射可用 `KeyEvent` 模拟写 widget 测试；UI 适配以真机实测为准。

## 6. 验收标准

1. 电视桌面出现 Jive 图标（横幅），遥控器可启动。
2. 仅用遥控器完成：首页翻页浏览 → 打开详情 → 选集 → 播放；播放中 OK 暂停/继续、左右 seek、上下集切换、返回退出。
3. 全程无必须触摸屏幕的步骤；每个可操作控件有清晰可见的焦点态。
4. 手机端 `flutter test` 全绿，既有交互无回归。

## 7. 分期

1. **P0 侧载实测（半天）**：零改动打包安装，确认播放链路在电视上可用、D-pad 现状能走到哪一步，输出问题清单。
2. **P1 基座（FR-1 + FR-2）**：manifest、横幅、强制横屏、焦点样式与关键组件焦点补齐。
3. **P2 播放页遥控（FR-3）**：按键映射 + 控制条/选集的 D-pad 操作。
4. **P3 布局与打磨（FR-4）**：横屏布局修正 + 真机实测回归。

## 8. 风险

- `GestureDetector` 独占交互点盘点遗漏，导致某些页面遥控器卡死 → P0 实测清单兜底。
- 电视 WebView/软键盘等系统差异导致搜索体验差 → 接受最低可用。
- 强制横屏的手机端回归 → 横屏仅对 TV（uiMode）生效，手机路径不动。
