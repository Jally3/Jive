# Jive VOD 源切换需求文档与改动计划

## 1. 文档信息

- 状态：待评审
- 平台：Flutter Android / iOS
- 本期核心：支持全局浏览源选择、搜索页局部来源切换，以及详情页仅针对当前视频切换播放来源
- 数据策略：第一阶段客户端直连已配置的合法 VOD 源，保留迁移到自有后端 Source Adapter 的能力

## 2. 背景与目标

当前 `StormVideoRepository` 将暴风资源地址写死，列表、分类、搜索、详情和播放均依赖同一来源。视频、收藏、历史和详情缓存只使用第三方 `vod_id`，无法安全支持多源。

本期目标：

1. 用户可设置首页、分类和新搜索会话默认使用的全局浏览源。
2. 搜索默认展示当前源结果，同时后台探测最多 3 个备用源并显示结果数量；用户可只切换当前搜索页来源。
3. 用户可在详情页为当前视频选择其他播放来源，不改变全局浏览源。
4. 切换后仍能正确刷新详情、剧集和失效播放地址。
5. 不同源的相同 `vod_id` 不发生缓存、收藏或历史冲突。
6. 新增源尽量只增加配置或 Adapter，不修改页面业务流程。

本期不实现帐号同步、跨源内容自动合并、无确认的播放自动换源、用户任意输入接口地址，以及服务端聚合与转码。

## 3. 核心概念

### 3.1 全局浏览源

决定首页、分类和搜索从哪里获取内容。切换后刷新这些页面及分类状态，选择结果持久化到本机。

### 3.2 当前视频来源

详情页会话中的局部状态，决定当前详情、剧集和播放地址来自哪个源。它初始等于进入详情时视频所属源，可以独立切换，且不得修改全局浏览源。

### 3.3 当前搜索页来源

搜索页会话中的局部状态。它初始等于全局浏览源，用户点击来源标签后只切换当前关键词的结果列表，不修改全局浏览源。输入新关键词时继续使用当前搜索页来源；重新创建搜索页时恢复为全局浏览源。

### 3.4 内容与资源

- “内容”表示用户认知中的同一影片。
- “资源”表示某个 VOD 源中的具体记录，由 `sourceId + sourceVideoId` 唯一标识。
- 第一阶段不建立可靠的统一内容 ID；跨源匹配结果必须允许用户确认。

## 4. 用户入口与交互

### 4.1 首页快捷入口

首页标题区域右上角显示当前源名称，例如“暴风资源 ▼”。点击打开源选择 Bottom Sheet。选择后：

1. 保存新的全局源。
2. 清空首页分类选择、分页结果和错误状态。
3. 重新获取分类与第一页。
4. 搜索页下次搜索使用新源。

### 4.2 我的 → 内容源

提供完整管理页，用于查看已启用源、设置默认源、检测可用性和查看最近检测结果。第一阶段仅支持内置白名单源，不允许编辑 URL。

### 4.3 搜索页局部来源

搜索结果上方显示当前源、3 个备用源和“更多”入口：

```text
[暴风 24] [来源 A 18] [来源 B 6] [来源 C 0] [更多 ▾]
```

- 用户停止输入 600ms 后立即请求当前搜索页来源。
- 同一关键词后台最多探测 3 个备用源，只获取第一页和接口可提供的总数，不获取详情或播放地址。
- 备用源按“最近使用、健康状态、响应速度、配置优先级”动态选择；排除近期连续失败的源。
- 点击已探测来源时立即展示其缓存第一页，只切换当前搜索页来源。
- 点击“更多”展示全部已启用源：已查询显示数量，未查询显示“未搜索”，失败显示“请求失败”。
- 打开“更多”不得自动请求其余全部源。点击某个未搜索源时按需查询并切换；列表底部提供用户主动触发的“检测全部来源”。
- 当前源无结果时立即启动备用探测；有结果时可延迟 300ms，减少用户继续输入造成的无效请求。

数量展示必须反映数据能力：接口提供 `total` 时显示准确数量；只能判断分页时显示 `20+`；无法获得总数时显示“有结果”，不得将第一页条数冒充总数。

### 4.4 详情页播放来源

详情页与搜索页采用一致的横向来源标签视觉，但使用更节制的按需请求策略。在播放按钮下方、剧集区域上方显示初始状态：

```text
播放来源                         暴风 · 36 集
[暴风 36集] [检测其他来源] [更多 ▾]
```

用户主动检测后显示：

```text
播放来源
[暴风 36集] [来源 A 有资源] [来源 B 40集] [来源 C 0] [更多 ▾]
```

详情页正常打开时只请求当前视频所属源，不自动请求 3 个备用源。点击“检测其他来源”后才并发搜索最多 3 个备用源；搜索到候选时先显示“有资源”，仅在用户点击该来源后获取候选详情和准确集数。当前源没有剧集、播放地址解析失败或连续超时时，可以提前提示查找备用来源，但不得未经用户确认自动切换影片。

来源标签状态规范：

- `暴风 36集`：当前活动来源，已获取准确剧集数。
- `来源 A 有资源`：找到候选，尚未获取候选详情。
- `来源 B 40集`：候选已确认并加载详情。
- `来源 C 0`：没有匹配结果。
- `来源 D …`：正在检测。
- `来源 E —`：尚未检测。
- `来源 F !`：请求失败，可手动重试。
- 电影使用“正片”，更新中的剧集可使用“更新36”，不得用裸数字混淆搜索结果数量。

点击“更多”展示全部来源及状态。打开弹窗不得自动请求全部源；点击“未检测”来源时按需搜索，底部提供显式“检测全部来源”。来源超过 6 个或处于移动网络时，执行全部检测前提示可能产生额外流量。

选择其他来源时：

1. 使用当前影片标题在目标源搜索。
2. 标准化标题并比较年份、类型、地区、演员和集数等字段。
3. 单一高置信度候选可标记“推荐”，但仍展示确认信息。
4. 多候选时展示候选列表，由用户选择。
5. 获取候选详情并确认存在可用剧集。
6. 替换详情页的局部活动资源，保留全局源不变。
7. 尽量按剧集名称或序号保留当前选集；无法匹配时回到第一集并提示。

内容源与同一源内的播放线路必须分开定义。内容源表示“暴风资源 / 来源 A / 来源 B”；播放线路表示同一资源的 `vod_play_url` 中以 `$$$` 分隔的线路。第一期界面可以只实现内容源切换，但解析模型应保留 `PlaybackLine`，不得继续默认丢弃第二条及后续有效线路。

### 4.5 异常恢复入口

列表请求失败时提供“重试”和“切换内容源”。详情解析失败时提供“重试当前来源”和“切换来源”。播放器失败时先刷新当前资源地址；跨源查找应返回详情页完成候选确认，不静默播放其他影片。

## 5. 功能规则

### 5.1 来源切换

- 全局源和详情页局部源是两个独立状态。
- 已打开详情页始终绑定其活动资源，不跟随之后的全局源变化。
- 播放器接收完整资源引用，地址失效时从原资源所属源刷新。
- 切换过程中禁用重复操作，旧请求结果不得覆盖新选择。
- 切换失败时保留当前可用详情和剧集，不显示半完成状态。

### 5.2 多源搜索与流量控制

- 默认每个关键词最多自动请求 4 个源：1 个当前源和 3 个备用源，不默认请求全部源。
- 关键词少于 2 个字符时不探测备用源；同时最多执行 2 个备用请求，单源超时 5～8 秒。
- 每个来源独立保存分页、加载、错误和总数状态；加载更多只请求当前搜索页来源。
- 相同“关键词 + 来源 + 页码”缓存 5～10 分钟，切回已查询来源不得重复请求。
- 搜索词变化时递增 generation，旧请求结果不得写入新搜索会话。
- 单源失败不影响其他源；连续失败源应临时退出自动探测，但仍可由用户手动重试。
- 下拉刷新只刷新当前搜索页来源，不连带刷新所有备用源。
- 移动网络可将备用探测数量降为 1，Wi-Fi 下保持最多 3 个；网络类型策略可在后续迭代启用。
- 多源结果第一阶段按来源独立展示，不做仅凭标题的激进去重或统一排序。

### 5.3 跨源匹配

建议匹配字段按优先级使用：标准化标题、年份、季/部信息、类型、演员、导演、地区和集数。仅靠标题不能视为确定匹配。候选应展示来源、标题、年份、封面、更新状态和集数。

详情页来源检测不得复用搜索页“默认 1+3 自动探测”规则：普通详情访问只加载当前源，用户点击“检测其他来源”后才探测最多 3 个备用源。候选搜索结果可以短时复用搜索缓存，但准确剧集数必须来自候选详情。切换完成前继续展示旧详情，目标源失败时不得清空当前资源。

### 5.4 收藏与历史

- 所有资源键使用 `globalId = sourceId:sourceVideoId`。
- 第一阶段收藏仍保存具体资源，不自动把不同来源合并为一条收藏。
- 详情页切源不会自动改变收藏；用户收藏时收藏当前活动资源。
- 观看历史记录实际播放的来源和资源 ID，继续播放时从该来源刷新地址。
- 旧本地数据缺少 `sourceId` 时迁移为默认值 `storm`。

### 5.5 安全与合规

- 只允许 HTTPS 和应用内置白名单源。
- 不在客户端配置密钥；如源需要鉴权，应通过自有后端接入。
- 发布前确认每个内容源的授权、地区政策和应用商店合规性。
- 日志不得记录完整带鉴权参数的播放 URL。

## 6. 数据与架构设计

### 6.1 新增模型

```dart
class VodSource {
  final String id;
  final String name;
  final Uri baseUri;
  final String adapterType;
  final Set<int> featuredCategoryIds;
}

class VideoRef {
  final String sourceId;
  final String sourceVideoId;
  String get globalId => '$sourceId:$sourceVideoId';
}

class PlaybackLine {
  final String id;
  final String name;
  final List<Episode> episodes;
}
```

`Video` 增加 `sourceId`、`sourceVideoId`，并补充用于匹配的 `year`、`area`、`actors`、`director`（接口缺失时允许为空）。详情模型保留 `playbackLines`；第一期默认选用第一条有效线路。`Episode.id` 仍为源内标识，跨源保持剧集时优先比较规范化名称和解析后的集数。

### 6.2 Adapter 与 Repository

```text
VodSourceRegistry
  → VodSourceAdapter（MacCmsV10Adapter / 其他协议 Adapter）
  → VideoRepository
  → 列表、分类、搜索、详情、播放
```

同协议源复用 Adapter，仅传入不同配置。Repository 方法必须接收 `VodSource` 或 `VideoRef`，不得依赖一个可变的全局 `baseUrl`。详情缓存键使用 `globalId`，不同源缓存相互隔离。

### 6.3 状态管理

- `vodSourceRegistryProvider`：提供内置源列表和 Adapter。
- `selectedVodSourceProvider`：全局浏览源，持久化到 `SharedPreferences`。
- `videoRepositoryProvider`：统一访问入口，不持有可变源。
- 搜索页使用独立的 `MultiSourceSearchController`，维护局部活动源和每个来源的请求状态。
- 详情页局部维护 `activeVideo`、`matches`、每个来源的检测状态、`switchingSourceId` 和请求 generation；不得读取或写入全局源来完成局部切换。

当前首页和搜索页在 `initState` 中固定持有 `PagedVideoController`。首页全局切源时需要重建 Controller；搜索页不再复用单源 `PagedVideoController`，改用专用协调器：

```dart
class SearchSessionState {
  final String keyword;
  final String activeSourceId;
  final Map<String, SourceSearchState> sources;
  final int generation;
}

class SourceSearchState {
  final List<Video> items;
  final int nextPage;
  final int? total;
  final bool hasMore;
  final bool loading;
  final bool queried;
  final String? error;
}
```

`VideoPage` 增加可空的 `total`。Adapter 不提供总数时保持 `null`，由 UI 降级显示。

## 7. 页面状态与错误处理

详情页至少覆盖以下状态：

- 当前来源正常。
- 尚未检测其他来源。
- 正在检测其他来源。
- 找到候选但尚未加载详情。
- 无匹配结果。
- 单一推荐候选。
- 多候选待确认。
- 正在切换并加载详情。
- 目标源不可用或没有播放地址。
- 切换成功但原剧集无法匹配。

在切换完成前继续展示旧详情；成功后一次性替换。不同来源的检测互不阻塞，用户退出页面后，异步结果不得更新已销毁页面。

搜索页至少覆盖：当前源加载、备用源探测、准确数量、估算数量、未搜索、无结果、单源失败、全部失败和缓存结果。来源标签的加载或失败状态不能遮挡当前源已返回的结果。

## 8. 验收标准

1. 全局源切换后，首页和分类重新加载，新建搜索页默认使用新源。
2. 每次搜索自动请求当前源和最多 3 个备用源，不自动请求其余全部源。
3. 来源标签正确显示准确数量、`N+`、“有结果”、“未搜索”或失败状态。
4. 点击备用来源只切换当前搜索页，并立即复用已探测的第一页；全局源保持不变。
5. “更多”打开时不产生全源请求；点击未搜索来源或“检测全部来源”后才发起对应请求。
6. 每个来源独立分页和报错，慢源或失败源不阻塞当前结果；旧关键词响应不覆盖新关键词。
7. 详情页正常打开时只请求当前源，不自动检测备用源；点击检测后最多探测 3 个备用源。
8. 详情来源栏与搜索页保持一致的横向标签视觉，并正确区分“剧集数”“有资源”“未检测”和失败状态。
9. 打开详情页“更多”不触发全源请求；未检测来源按需请求，“检测全部来源”必须显式触发。
10. 详情页从源 A 切至源 B 后，返回首页仍显示全局源 A。
11. 详情页的简介、集数、剧集和播放均来自当前局部源 B。
12. 播放失败重试仍请求源 B，不读取当前全局源。
13. 两个源具有相同 `vod_id` 时，缓存、卡片 Key、收藏和历史互不覆盖。
14. 多个同名候选不会未经确认自动播放。
15. 切源失败不清空当前详情，用户可继续使用原来源。
16. 当前剧集在目标源存在时被保留；不存在时给出明确提示。
17. 同一内容源存在多条播放线路时，解析模型不会丢弃后续有效线路。
18. App 重启后全局源保持；收藏和历史可从正确来源恢复。
19. `flutter analyze` 与全部 `flutter test` 通过。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 同名影片误匹配 | 播放错误内容 | 增加元数据评分，多候选必须确认 |
| 各源分类 ID 不一致 | 分类为空或错位 | 分类策略放入每个源配置/Adapter |
| 剧集命名不一致 | 切源后选集错位 | 名称规范化 + 集数解析 + 用户提示 |
| 源不稳定或限流 | 切换失败 | 超时、可重试、健康状态、保留旧详情 |
| 旧数据只有裸 ID | 收藏/历史失效 | 版本化迁移并默认映射到 `storm` |
| 页面缓存旧 Repository | UI 与源状态不一致 | Repository 按引用请求，切全局源时重建 Controller |
| 每次输入请求过多来源 | 流量、电量和限流压力 | 600ms 防抖、1+3 上限、并发 2、短时缓存和按需全源检测 |
| 数量并非真实总数 | 误导用户 | `total` 可空，分别显示准确数量、`N+` 或“有结果” |
| 慢源拖累搜索首屏 | 搜索响应迟缓 | 当前源优先增量展示，备用源独立超时和错误状态 |
| 搜索词发送给多个第三方 | 隐私与合规风险 | 仅探测已启用白名单源，明确搜索范围，正式版迁移后端 |
| 每次打开详情就探测多源 | 不必要的流量与限流 | 默认只请求当前源，用户触发或当前源异常时才检测备用源 |
| 详情候选只有标题相同 | 误切到同名影片 | 先显示“有资源”，加载详情并由用户确认后再切换 |
| 内容源与播放线路混淆 | 丢失可用线路或交互含义错误 | 分开建模 `VodSource` 与 `PlaybackLine`，标签栏只表示内容源 |
| 客户端暴露第三方地址 | 合规和可维护性风险 | 仅用于 MVP，正式版迁移自有后端 |

## 11. 评审决策项

请在开发前确认：

1. 本期是否同时实现全局浏览源，还是只实现详情页局部来源切换。
2. 第一批接入哪些来源，以及是否已确认合法授权与稳定性。
3. 详情页高置信度单一候选是否仍要求用户确认（推荐：首次确认）。
4. 收藏语义采用“具体来源资源”（本期推荐），还是投入更多工作建设跨源统一内容实体。
5. 局部切源选择是否仅本次详情会话有效（推荐），还是记住该影片最近成功来源。
6. 是否允许用户添加自定义源（本期推荐：不允许）。
7. 是否接受第一阶段客户端直连、第二阶段迁移自有后端的路线。
8. 是否确认搜索默认采用“当前源 + 最多 3 个备用源”，而不是默认请求全部源（推荐：确认）。
9. 移动网络是否首版就将自动备用源降为 1 个，还是作为后续优化（推荐：后续优化）。
10. “检测全部来源”是否需要二次流量提示（推荐：来源超过 6 个或移动网络时提示）。
11. 是否确认详情页默认不自动探测备用源，仅在用户点击或当前源异常时检测（推荐：确认）。
12. 第一版是否只保留多线路数据模型、暂不展示“播放线路”选择控件（推荐：是）。

## 12. 推荐评审结论

建议批准“完整数据底座 + 基础全局入口 + 搜索页局部切源 + 详情页局部切源”的范围：先完成来源身份、Adapter 和数据迁移，再实现搜索页 1 个当前源加最多 3 个备用源的增量搜索，最后交付详情页局部切源。其余来源只在用户点击后查询，“检测全部来源”必须显式触发；全局入口不做自动故障转移。跨源匹配第一版由用户确认，收藏按具体资源保存，局部选择仅当前会话有效。该范围兼顾资源覆盖率、流量和稳定性，也为后续后端聚合保留升级路径。
