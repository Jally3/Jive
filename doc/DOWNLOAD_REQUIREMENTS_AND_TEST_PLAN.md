# 下载功能需求与测试审查文档

> 用途：作为后续下载功能开发、测试验收和代码审查的统一基线。
>
> 范围：用户主动下载、下载管理、离线播放、下载完成后的广告过滤，以及与自动缓存的边界。

## 1. 功能边界

Jive 的缓存能力分为两个相互独立的部分：

| 能力 | 触发方式 | 目的 | 管理页面 |
| --- | --- | --- | --- |
| 显式下载 | 用户点击下载按钮 | 下载当前集或多集，供用户离线观看 | 下载管理 |
| 自动缓存 | 在线代理播放时自动发生 | 提升边下边播和重复播放体验 | 自动缓存 |

两者可以复用相同的资源文件，但不能混淆任务状态、页面展示和完成条件。

显式下载默认启用广告过滤；普通边下边播是否过滤广告由现有 `adFilterEnabled` 配置决定。

## 2. 下载入口

### 2.1 详情页

- 剧集列表不显示每集下载按钮。
- 播放按钮附近只显示一个“下载”按钮。
- 点击后打开剧集多选弹窗。
- 当前选集默认选中。
- 支持多选。
- 用户点击确认后才创建任务，取消不能创建任务。
- 详情页 AppBar 右上角提供“下载管理”入口。
- 下载管理和自动缓存管理进入两个独立页面。

### 2.2 播放页

- 非全屏状态的底部控制栏显示下载按钮。
- 下载按钮只创建当前集任务，不打开选集弹窗。
- 使用当前播放会话的 `PlaybackSelection`，不能重新选择线路。
- 全屏状态隐藏下载按钮。
- 控制栏自动隐藏时，下载按钮同步隐藏。
- 已下载显示完成状态。
- 下载中禁止重复创建相同任务。
- 失败后允许点击重试。
- 切集或播放器销毁不能取消已经创建的下载任务。
- 没有稳定 identity、非 HLS 或不支持缓存时，应显示固定中文原因。
- 接口返回 HTML 播放页而非媒体直链时，应先从受信任的 HTTPS 页面解析并验证真实媒体 URL；在线播放和下载必须复用同一解析结果。
- 多条播放线路同时存在时，默认优先直接 HLS/MP4 线路，其次才是可解析的 HTML 包装线路。

## 3. 显式下载任务

### 3.1 任务状态

任务至少支持以下状态：

- `queued`：排队中
- `downloading`：下载中
- `paused`：已暂停
- `completed`：已完成
- `failed`：失败，可重试
- `cancelled`：已取消

状态必须持久化。应用重启后不能把有效任务误判为不存在，也不能把完整缓存误判为未下载。

### 3.2 任务信息

任务应保存：

- 视频标题和剧集信息；
- `sourceId`、`sourceVideoId`；
- `playbackLineIdentity`、`episodeIdentity`；
- 可恢复播放所需的 `playbackUrl`；
- `contentKeyHash`、`revisionKeyHash`；
- 期望资源数、已完成资源数；
- 已下载字节数、总字节数；
- 最近 3 秒平均下载速度；
- 广告过滤版本和过滤置信度；
- 错误类型和创建/更新时间。

任务恢复优先使用持久化的播放 URL 和缓存 Manifest，不能在断网时强制重新请求远端线路信息。

## 4. 混合下载策略

显式下载采用“先下载原始资源，完成后本地过滤”的策略。

### 4.1 正常流程

```text
获取最终 Media Playlist
        ↓
检查 HLS 能力、直播、加密和未知标签
        ↓
保存 source_manifest.m3u8
        ↓
生成原始资源计划
        ↓
下载并校验全部原始资源
        ↓
本地运行 AdFilter(enabled: true)
        ↓
生成过滤后的 playable.m3u8
        ↓
保存 timeline.json、过滤版本和置信度
        ↓
标记 offlinePlayable
```

### 4.2 原始资源要求

- 下载阶段允许请求广告片段。
- 原始视频片段、广告片段、初始化资源和标准 AES-128 密钥都必须按照原始 Manifest 枚举。
- 相同 URL 的资源必须复用同一个 `resourceId`。
- 已完整缓存的资源可以跳过重复下载。
- 下载总资源数、完成条件和已下载字节数以实际原始资源计划为准。
- 原始资源全部成功提交后，才允许开始最终过滤和完成标记。

### 4.3 过滤结果要求

- `source_manifest.m3u8` 必须保留原始内容。
- `playable.m3u8` 必须不包含被识别为广告的片段。
- `timeline.json` 保存被移除的时间区间、过滤版本和置信度。
- 过滤后的 Manifest 必须引用已经下载的资源 ID，不能因为过滤再次请求网络。
- 广告识别结果为空时，使用完整原始内容。
- 低置信度结果遵循“宁漏勿错”，不得误删正常内容。
- 过滤算法异常时，优先回退原始 Manifest；若原始 Manifest 或资源不完整，则任务失败，不能标记为完成。
- 过滤版本变化时，应产生新的下载 revision，避免新旧 Manifest 混用。

### 4.4 离线播放

- 下载完成后播放器显示“缓存播放”，不显示“边下边播”。
- 离线播放读取已保存的 `playable.m3u8`。
- 离线播放不重新运行广告算法。
- 离线启动不应请求远端 Manifest、线路解析接口或视频资源。
- 本地代理必须能返回 Manifest、初始化资源和普通/Range 资源请求。
- 播放进度需要使用 `timeline.json` 在原始时间轴和过滤后时间轴之间转换。

## 5. 下载进度与大小显示

### 5.1 总大小已知

当所有资源都能获得有效长度时，显示：

```text
已下载大小 / 视频总大小
```

进度条按字节计算：

```text
downloadedBytes / totalBytes
```

### 5.2 总大小未知

HLS Manifest 通常不提供完整视频文件大小；服务器也可能不返回 `Content-Length`。此时禁止显示虚假的字节百分比。

应显示：

```text
已下载大小 · 片段 18/96
速度 2.4 MB/s
```

进度条按资源片段数计算：

```text
completedResourceCount / expectedResourceCount
```

如果片段数也尚未解析完成，才使用不确定进度条并显示“片段数计算中”。

### 5.3 自动切换

- 开始下载时总大小未知：显示片段进度。
- 所有资源长度已知：切换到字节进度。
- 下载完成：总大小必须显示实际写入磁盘的准确大小。
- 切换时不能清零已下载大小，也不能出现进度倒退。
- 当前下载速度使用最近 3 秒滑动窗口，每秒刷新一次。
- 没有有效速度样本时显示 `0 B/s`，不能展示异常的大数或负数。

## 6. 下载管理页面

下载管理页面显示：

- 视频标题和剧集；
- 当前状态；
- 进度条；
- 已下载大小和总大小，或片段进度；
- 当前下载速度；
- 排队、暂停、继续、重试、取消操作；
- 已完成任务可直接进入离线播放。

页面不得把自动缓存条目当作显式下载任务展示，也不得把边下边播状态显示为“下载完成”。

## 7. 存储、配额和资源一致性

- 下载文件放在应用持久化支持目录，不能依赖系统临时 Cache 目录的 2.5G 限制。
- 不设置固定的最高 2.5G 下载上限。
- 实际可用空间、已有 Jive 缓存和安全余量共同决定可写配额。
- 配额不足时任务失败或按既定策略暂停，不能伪造完成状态。
- `reserve`、写入、校验、提交任一步失败都不能标记资源为完整。
- 重复提交同一个资源不能重复增加完成计数或字节数。
- 文件缺失、文件大小不匹配时，启动 reconcile 必须回退资源状态并重新计算计数。
- 删除采用持久化 `deleting` 状态；删除失败时启动后应继续清理。
- 任务取消不能误删其他任务或自动缓存正在使用的资源。

## 8. 不支持和回退策略

以下内容不进入显式下载过滤流程：

- 非 HLS 格式；
- 直播流；
- DRM、`SAMPLE-AES`、非 identity `KEYFORMAT` 或需要在线许可证的加密流；
- 未知或不支持的 HLS 标签；
- Manifest 不完整；
- 没有稳定 PlaybackSelection identity。

固定回退原则：

- Manifest 解析失败：任务失败并显示固定原因。
- 资源网络失败：任务失败，可重试。
- 配额不足：任务失败或暂停，不能标记完成。
- 缓存写入失败：任务失败，保留可恢复的任务信息。
- 过滤失败：已有完整原始资源时回退原始 Manifest；原始资源不完整时失败。
- 播放器离线启动：优先读取本地缓存；本地缓存不存在时才允许走在线流程。

底层异常信息不得直接展示给用户，尤其不能展示完整 URL、Cookie 或敏感请求头。

## 9. 并发、暂停和恢复

- 下载并发数由 `PrefetchConfig` 或下载管理器配置控制，默认值当前为 5。
- 同一任务只能有一个实际运行实例。
- 暂停后不应继续创建新的资源请求。
- 暂停任务恢复后复用已完成资源和部分资源。
- 任务恢复时必须重新检查文件和资源索引，不能只相信任务 JSON。
- 切换剧集、退出播放器或销毁页面不能取消已入队的任务。
- 应用生命周期进入后台时按现有策略暂停或保持前台任务，不得丢失任务状态。

## 10. 测试验收清单

### 10.1 入口和 UI

- [ ] 详情页剧集列表没有每集下载按钮。
- [ ] 详情页只有一个下载按钮。
- [ ] 详情页下载弹窗支持多选，当前集默认选中。
- [ ] 取消弹窗不创建任务，确认后才创建任务。
- [ ] 播放页非全屏显示当前集下载按钮。
- [ ] 播放页全屏隐藏下载按钮。
- [ ] 控制栏隐藏时下载按钮同步隐藏。
- [ ] 播放页下载使用当前线路和当前剧集 identity。
- [ ] 下载管理和自动缓存管理是两个独立页面。

### 10.2 任务状态

- [ ] 任务能够排队、开始、暂停、继续、取消、失败和重试。
- [ ] 下载中重复点击不会创建重复任务。
- [ ] 应用重启后任务状态和缓存状态一致。
- [ ] 播放器切集或销毁不会取消已创建任务。
- [ ] 失败任务可以重新下载，且不会重复计数。

### 10.3 下载和广告过滤

- [ ] 下载先解析原始 Media Playlist。
- [ ] 含广告的 fixture 中，广告资源在原始下载阶段会被请求。
- [ ] 原始资源全部完成后才执行本地广告过滤。
- [ ] 广告 URI 不出现在最终 `playable.m3u8`。
- [ ] `source_manifest.m3u8` 保留广告 URI 和原始内容。
- [ ] `timeline.json` 保存移除区间、过滤版本和置信度。
- [ ] 广告识别为空时，最终 Manifest 与原始内容等价。
- [ ] 过滤异常时能回退原始 Manifest，不能产生错误的完成状态。
- [ ] 过滤后的离线播放不请求远端广告资源。
- [ ] 过滤后的缓存重启后仍可离线播放。
- [ ] 过滤版本变化后产生新的 revision。

### 10.4 进度、大小和速度

- [ ] 服务器返回 `Content-Length` 时显示准确总大小。
- [ ] 服务器不返回 `Content-Length` 时显示“已下载大小 + 片段 x/y”。
- [ ] 总大小未知时进度条按资源片段数推进，而不是无限滚动。
- [ ] 片段数也未知时显示“片段数计算中”。
- [ ] 总大小变为已知后切换到字节进度。
- [ ] 下载完成后显示实际准确大小。
- [ ] 速度按最近 3 秒计算并每秒刷新。
- [ ] 暂停、失败和完成状态下速度显示合理，不残留旧速度。

### 10.5 离线和回退

- [ ] 断网时已完成下载可以直接打开播放。
- [ ] 断网时不会因为重新解析远端线路而失败。
- [ ] 本地 Manifest、初始化资源、AES-128 密钥和普通资源请求均返回成功。
- [ ] Range 请求能够读取本地缓存资源。
- [ ] 缓存不存在时显示固定回退原因，不暴露底层异常。
- [ ] DRM、SAMPLE-AES、直播、非 HLS 和未知标签按策略拒绝下载。
- [ ] 标准 AES-128 流会缓存 16 字节密钥并把最终 Manifest 的密钥 URI 重写到本地代理。
- [ ] AES-128 密钥缺失、长度异常或获取失败时不得标记 `offlinePlayable`。

### 10.6 缓存一致性

- [ ] 缺失完整资源后 reconcile 会回退完成状态。
- [ ] 资源文件大小不匹配时不会继续标记完整。
- [ ] 重复提交资源不会虚增完成数和字节数。
- [ ] 配额不足不会留下错误的 `offlinePlayable`。
- [ ] 删除失败的条目重启后会继续清理。
- [ ] 自动缓存和显式下载不会互相错误删除资源。

## 11. 代码审查重点

审查下载相关改动时重点确认：

1. 是否把显式下载和自动缓存的任务、页面和完成状态混在一起。
2. 是否在广告过滤前就下载了原始资源，或错误地先过滤后下载。
3. 是否把 `expectedResourceCount`、`committedResourceCount` 和最终 Manifest 的片段数混用。
4. 总大小未知时是否错误显示了字节百分比。
5. 是否在未完成所有原始资源时提前设置 `offlinePlayable`。
6. 过滤失败时是否仍能播放原始资源，或错误保留了不一致的 timeline 元数据。
7. 离线播放是否仍会无条件请求远端 Manifest、播放线路或视频资源。
8. 是否正确持久化和恢复 `playbackUrl`、identity、revision 和过滤版本。
9. 是否存在并发下载同一资源导致重复写入、重复计数或文件损坏。
10. 是否把底层网络异常、URL、Cookie 或请求头直接展示给用户。
11. 是否破坏 HEAD、Range、BYTERANGE 和本地代理行为。
12. 是否为新增逻辑补充单元测试、缓存恢复测试和离线播放测试。

## 12. 当前明确不在范围内

- 系统级后台下载；
- 系统通知栏下载通知；
- 断点续传 `.part` 的 206 合并；
- 在下载前通过 HEAD 请求保证获取总大小；
- DRM/SAMPLE-AES 内容解密；标准 AES-128 仅原样缓存密钥和加密分片，由系统播放器解密；
- 直播流离线下载；
- 通过删除已下载文件来反向移除广告。
