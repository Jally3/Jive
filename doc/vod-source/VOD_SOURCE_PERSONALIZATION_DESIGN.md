# VOD 来源个性化方案：管理态、置顶/置底与本机编辑

日期：2026-10-17

分支：`codex/vod-source-preferences`

状态：P0 已实现并完成自动化回归；P1 与后续候选保留，真机及用户研究待开展

决策依据：[JTBD、机会方案树与实验设计](VOD_SOURCE_PERSONALIZATION_DISCOVERY.md)

## 1. 产品判断

先帮助用户保存和复用“哪些源常用、哪些源适合哪类内容”的经验。首版采用“置顶 + 内容标签 + 私人备注 + 选源筛选”。分类首选、首页快捷频道和自动切源作为后续验证项，不再作为首版前提。

理由：用户已明确表达优先源与不同内容优势；是否需要按类型自动切源、是否愿意绑定源内分类，仍未确定。标签可以表达“A、C 都适合综艺”，不要求每类只有一个首选。

核心体验：给 A 源标记“综艺”、给 B 源标记“电影”；以后打开选源弹层点“综艺”，即可找到 A 源，点选后按现有逻辑切换。

## 2. 首版范围与优先级

| 优先级 | 能力 | 解决的问题 |
| --- | --- | --- |
| P0 | 多源置顶 / 取消置顶 | 常用源难找 |
| P0 补充 | 原地选择/管理切换、置底/取消置底 | 管理跳页、不常用但希望保留备用 |
| P0 | 多选内容标签：电影、剧集、动漫、综艺 | 记住不同源的内容优势 |
| P0 | 私人备注、可选显示名 | 表达“综艺全、更新快”等个体经验 |
| P0 | 选源弹层标签筛选、源行快捷操作 | 在需要选择时找到适合的源 |
| P0 | 本机保存、恢复单源个性化设置、统一展示 | 下次继续使用同一套经验 |
| P1 | 置顶组拖拽、禁用源、搜索参与开关 | 更细的列表管理与来源治理 |
| P1 候选 | 明确内容上下文中的分类首选提示 | 减少搜索/详情换源决策成本 |
| 后续候选 | 首页跨源快捷频道、自动按类型切源 | 待验证的分类导航与自动化需求 |

连接配置继续由远端维护。P0 通过私人标记完成编辑，P1 再开放启用和搜索参与控制。未配置的用户沿用远端源目录及现有选源流程。

## 3. 概念与规则

| 概念 | 用户含义 | 是否会切源 |
| --- | --- | --- |
| 当前 | 此刻正在浏览或当前局部页面使用的来源 | 用户选源后改变 |
| 置顶 | 希望在列表前面找到它 | 否 |
| 置底 | 不常用但保留备用，不等于停用 | 否 |
| 内容标签 | 我认为这个来源适合哪些内容 | 否 |
| 备注 | 我自己的使用经验 | 否 |

标签是用户个人判断，不代表应用检测或官方推荐。每源可有 0–4 个标签，同一标签可标记多个源；标签不改变来源的搜索、下载或播放能力，不作为自动探测的排除条件。

## 4. 选源弹层

保留“资源站 / 高清站”两个分组，默认选择态：行展示显示名、置顶/置底标记、当前状态、标签和一行备注，点击来源才切源并关闭弹窗；无备注时使用现有来源说明或域名。管理操作在选择态隐藏。

点击标题右侧“管理”在当前弹窗内进入管理态，不跳转新页面。管理态行点击不切源；行尾提供至少 44pt 的快捷置顶按钮及更多菜单：置底/取消置底、编辑、检测、恢复此源设置。点击“完成”回到选择态，不关闭弹窗，也不是统一保存按钮。模式切换保留分组、筛选和滚动位置；关闭再打开默认选择态。置顶变更仍回到顶部展示新排序。

存在任何个人标签时，显示“全部 / 电影 / 剧集 / 动漫 / 综艺”单选筛选行；没有任何标签时不显示筛选行，编辑入口说明可添加标签。筛选只查找用户已标记的来源，文案为“按我的标签筛选”。

筛选标签选中态仅通过背景和文字颜色区分，不显示勾选图标；编辑面板中的多选标签交互保持不变。

同一个筛选条件应用到两个分组，显示各组匹配数量。无匹配项时提示“这里还没有标记为综艺的来源”，提供“显示全部”，不能误报来源失效或没有综艺内容。当前源被筛掉时不偷偷插入结果，也不切换当前源。

每次重新打开弹层默认“全部”，避免上次筛选隐藏来源。默认打开当前源所属分组。当前分组存在用户置顶时初始定位列表顶部，让置顶可见；没有置顶时保留当前源定位。筛选或编辑后重新计算位置，保证当前屏幕能看到结果。

## 5. 编辑面板与来源管理

编辑面板包含显示名（可选，最多 30 个字符）、内容标签（多选）、私人备注（最多 80 个字符）和保存/取消。输入去掉首尾空白，显示名留空恢复远端名称，备注留空即清除；保存后才生效，取消无副作用。界面说明“仅保存在本机”。

设置入口复用与弹窗相同的 SourcePanel，默认管理态，显示“完成”；完成后退出管理态，仍停留当前页面，可以选择来源而不退出页面，再次点击“管理”可继续管理。返回导航在加载和错误状态也保留。健康检测、分组、筛选、编辑、置顶/置底及不可用设置清理使用同一实现，不再维护两套列表行为。

来源列表按现有视觉规范收紧：名称与“当前”/置顶标记为主行，备注或域名为次行，标签按需追加。当前源以浅色背景区分，不显示整列单选圆圈；文字放大时允许状态独立换行，不固定行高。检测结果仅管理态显示，“检测全部”在管理态工具栏，单源检测位于更多菜单。完整检测时间与错误信息通过状态提示查看，读屏保留完整结果且避免重复播报；单源检测状态和结果在页面/弹窗间共享，同一源进行中不重复发请求。

“恢复此源设置”清除该源别名、标签、备注、置顶和置底，动作前确认；不清除当前源选择、健康记录、历史、收藏或下载。

排序规则：置顶组 → 普通组 → 置底组。新置顶放在置顶组首位，新置底追加到置底组末尾；两者互斥，设置一个时自动解除另一个。普通组按远端 priority / sourceId 排序，取消排序偏好后回到普通组。各分组分别展示相应子序列，管理页与弹窗一致。置底不隐藏来源、不停用、不修改自动检索策略，也不切换当前源。P0 不提供拖拽。

移除 dbku / 名称含“独播”的硬编码置顶，以远端 priority 保留目录推荐顺序，个人操作拥有最高列表优先级。

## 6. 首页、搜索和详情的边界

P0 首页保持已有布局，通过选源弹层的标签找源；仍按来源加载分类，不增加跨源分类绑定。标签“综艺”只筛来源，不会直接打开其综艺列表。相对于上一版，这是明确的能力收敛，需要在原型测试中观察是否足够。

P0 统一源名和置顶/置底排序。首页选源、来源管理、搜索/详情的“全部来源”使用同一三组排序。搜索/详情顶部来源标签将当前源放在首位，其余按同一顺序；搜索保留最多 3 个备用标签，其余通过“更多”访问。未请求的置顶源作为手动入口，解除置顶（包括改为置底）后未请求项退出快捷标签。

所有入口响应同一偏好状态，包括已打开的“全部来源”弹层。置顶不自动切换正在浏览或播放的源，不额外发起搜索/检测，不扩大自动请求预算；自动备用源策略沿用现有健康、最近使用与请求预算。内容身份仍使用 sourceId。

P1 可在已知影片类型时突出匹配标签的来源，并提供“设为该类首选”；用户显式选择优先。标签允许多个，首选每类一个，两个概念分别存储。普通片名查询不通过猜测片名强制切源。

若后续验证首页分类导航才是主要成本，再设计 sourceId + categoryId 的快捷频道；源内分类映射必须由用户确认，并处理分类变更。若用户明确需要自动选源，再定义自动/手动模式、回退与撤销规则。

## 7. 数据与代码职责

采用“远端目录 + 本机个性化设置”的组合，不改写远端缓存。JSON 包含 schemaVersion=1、按 sourceId 索引的 displayName / tags / note，以及有序 pinnedSourceIds / demotedSourceIds；旧数据缺少置底字段时视为空，脏数据同时出现在两组时置顶优先，确保互斥。不保存 sourceId 之外的连接配置副本。

建议职责：

- `lib/domain/vod_source_customization.dart`：个人设置模型、标签枚举、序列化和规范化。
- `lib/data/vod_source/vod_source_customization_store.dart`：本机持久化、版本识别及损坏记录容错。
- `lib/data/vod_source/vod_source_customization_provider.dart`：初始化、串行更新、保存失败反馈。
- `lib/data/vod_source/vod_source_presentation.dart`：组合远端信息与个人显示名、标签、备注、置顶；提供统一排序和筛选。
- `lib/features/settings/source_edit_sheet.dart`：编辑面板。
- `lib/data/vod_source/vod_source_health_provider.dart`：共享检测状态、历史结果读取、去重、超时和结果持久化；不依赖某个页面生命周期。
- `lib/shared/source_selector.dart`：共享 SourcePanel，封装两种模式及分组/筛选/管理交互；设置页与弹窗仅提供外壳。

注册表继续负责源身份和 Adapter；显示名不写入 sourceId，不让个人设置导致 HTTP 客户端重建。UI 不直接读写存储。新增 Dart 文件时同步更新 `CODEBASE_MAP.md`。

更新串行执行，持久化成功后发布状态；失败保留原值，编辑面板保留用户输入并允许重试。先完成设置初始化再呈现个性化列表，避免旧值覆盖新操作。

## 8. 异常与恢复

- 远端改名/地址但 ID 不变：标签、备注、别名和置顶继续生效，连接使用最新远端配置。
- 远端移除来源：忽略其列表展示，不因个人设置把它恢复为可用；保留本机记录以便同 ID 恢复时复用。管理页可显示“已不可用的个性化来源”并允许清除该记录。
- 损坏记录：有效记录继续生效；未知标签忽略、重复置顶去重；整份损坏或未来版本使用默认展示并保留原始数据，直到用户显式保存。
- 编辑当前源：名称展示即时更新，不发起重新选源，不重建列表/播放器，不影响历史与下载身份。
- 窄屏与大字体：标签可换行，备注单行截断且编辑时可看全文；不沿用现有 72 固定行高造成裁切。更多按钮和键盘/方向键均可操作。
- P1 禁用/搜索开关需额外定义当前源回退、最后一个源保护与历史续播行为，P0 不提前加入这些状态分支。

## 9. 验收与交付

P0 验收：

1. A 源置顶后在管理页与对应选源分组排首，重启仍保留；取消后恢复目录排序。
2. A 标综艺、B 标电影，筛“综艺”仅列已标综艺的来源；同标签可有多个来源。
3. 点击标签、编辑、置顶不会改变当前源；点击来源行才执行现有选源行为。
4. 别名和备注在保存、取消、恢复、重启后表现一致；远端同 ID 更新不覆盖个人设置。
5. 连续保存、持久化失败、远端删除源、损坏数据不会串改其他来源设置。
6. 空标签结果可一键返回全部；高清站分组与当前源定位规则可理解。
7. 窄屏、大字体、键盘操作能完成编辑和选源，界面不截断关键操作。
8. 首页管理不新增页面，管理态行点击不切源，完成后仍可选择；设置默认管理态，切换模式不丢失分组/筛选/位置。
9. 置底与置顶互斥，退出或重启后保留，取消及恢复可撤销；四处完整列表同步排序且不新增自动请求。

本轮不增加自定义新增、删除或停用。目录源后续优先考虑可恢复的停用；自定义接入与删除需成对设计地址/Adapter 校验、重复识别和在用来源保护，单独评审。

交付顺序：先完成原型任务验证，再实现 P0 的存储与统一展示、编辑和筛选，最后进行回归与界面验收。开发检查使用 `fvm dart format lib test`、`fvm flutter analyze` 和 `fvm flutter test`，重点覆盖持久化、排序/筛选、保存失败和交互不误切源。

P0 已在当前分支实现，验证详情见 [实施记录](VOD_SOURCE_PERSONALIZATION_IMPLEMENTATION.md)。本方案的用户收益仍需实验验证；当前未开展外部用户原型研究，未增加遥测，尚未进行 Android/iOS 真机验收。
