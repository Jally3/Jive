# 鸿蒙下载空间检测修复

目标：修复鸿蒙未实现 `jive/cache` 导致剩余空间被误报为 0、下载立即失败的问题。用户已授权执行前一轮分析中的修复建议。

设计：复用现有平台通道，在 EntryAbility 中以应用 filesDir 查询所在文件系统的总容量和空闲容量；不申请额外权限，不使用系统根分区，不伪造容量。容量查询失败保留为独立错误，初始化与在线播放可降级，显式下载给出可重试的错误。确实没有空间时仍显示“存储空间不足”。每次下载尝试重新查询，以便重试可从临时故障恢复。

采用现有 ArkTS 原生 API；不引入第三方插件。Dart 层继续使用现有缓存配额与安全预留规则。

## 执行步骤

- [x] 格式化、静态分析、全量 Flutter 测试和鸿蒙 HAP 构建（全量测试存在下述两个已复现的基线失败）。
- [x] 覆盖安装并在模拟器验证实际下载有非零进度，更新文件地图和验证记录。

验证关注：大于 32 位容量的通道编码、查询错误与零容量区别、错误后的恢复、在线播放旁路、现有下载数据保留。

## 验证与审查记录（2026-10-28）

- 修复前模拟器 `/data` 仍有约 7.3 GB 可用；原生入口缺少通道，Dart 将异常转为 0。
- 平台查询回归先失败（缺少通道、平台异常、无效值均返回 0），实现后通过。
- 下载/缓存回归先失败，覆盖故障降级、真实零空间、恢复后重试和在线播放透传。相关 76 项测试通过。
- 即时重试回归发现旧任务清理未完成时 `resume` 会直接返回成功却未启动；现会等待失败任务清理后重试。
- 独立代码审查发现：在途租约扩容时，另一个任务触发的查询失败可能使缓存按零配额淘汰。新增回归先验证缓存被误删，再加查询错误保护，禁止据此淘汰。
- 首轮全量测试：778 通过，3 跳过，2 失败。失败用例为 `nav_overlay_test.dart` 的 `collapsed root row shows a transparent primary feed label`（纵坐标差 12），以及 `detail_page_test.dart` 的 `returning from the player expands the group of the played episode`（查找滚动节点失败）。在 `/tmp` 从修改前 HEAD 导出的独立副本上，两个用例均复现相同失败；本次不修改相关页面。
- 首轮静态分析无问题；HAP 构建成功，系统 UI 补丁收敛和官方 FVM 配置恢复通过。
- 在 API 21 ARM64 模拟器 `127.0.0.1:5555` 覆盖安装后，原有两个失败任务均保留。通过“全部继续”恢复，任务累计下载 43.8 MB、总速度约 2.3 MB/s、异常数为 0。取证后暂停两个任务并保留文件及进度。
- 最终检查：77 项相关测试全过；静态分析无问题；全量测试 779 通过、3 跳过，仅上述两个基线失败。并发保护回归由失败（缓存被删除）转为通过。
- 最终版本再次构建成功，以 `hdc install -r` 安装并启动；确认两个暂停任务和已写入的 78,035,648 字节（约 74.4 MiB）保留。官方 FVM 配置恢复通过。
