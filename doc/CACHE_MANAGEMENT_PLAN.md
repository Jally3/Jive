# 边播边下、广告过滤与缓存管理 —— 设计与实施计划

> 目标：在 `video_player`（ExoPlayer / AVPlayer）之上实现「边播边下、看过不重复耗流量、下次秒开」，并配套严格缓存管理与「我的」页缓存管理入口。
> 纯原理讲解见团队知识文档《边播边下 与 广告过滤 —— 纯原理讲解》。

## 2. 总体架构

```
┌──────────────┐        ┌─────────────────────┐        ┌──────────┐
│              │ 请求目录 │                     │ 已下载→ │ 本地磁盘  │
│   播 放 器    │───────→│  本地代理服务器        │────────→│ (片段缓存)│
│              │ 请求片段 │  (127.0.0.1:端口)   │        └──────────┘
└──────────────┘        │                     │ 未下载→ ┌──────────┐
                        └─────────────────────┘────────→│ 远端 CDN  │
                                 ↑                      └──────────┘
                        ┌─────────────────────┐
                        │   后台并发下载器       │
                        │ (按顺序把片段拉到本地) │
                        └─────────────────────┘
```

三个角色：

1. **播放器**——只认一个地址 `http://127.0.0.1:端口/play/<会话>.m3u8`，全程不换源
2. **本地代理服务器**——目录请求返回混合目录；片段请求本地命中直接吐文件，未命中转发回远端
3. **后台下载器**——有序并发下载片段，写盘后同步缓存索引

**关键决策**：由于代理对未下载片段自动跳回远端，播放器**从头到尾只认代理地址、永不换源**，「双轨启动 + 位置挂起恢复切换」可整体省略，用户无感地从纯在线→混合→全本地过渡。

## 3. 边播边下生命周期

### 阶段 1：决策（进入播放页瞬间）
- 用「剥掉时效 token 后 URL」的哈希定位缓存目录
- 完整命中 → 直接进代理模式（秒开）
- 部分命中 → 边播边下，已下载部分直接用
- 未命中 → 全新开始，边播边下
- 直播流（m3u8 无 `#EXT-X-ENDLIST`）→ 保持纯在线，不走缓存

### 阶段 2：代理优先起播
- 播放器立即以代理 URL 开始播放，第 0 片优先下载，零等待

### 阶段 3：下载调度（贯穿全程）
- 并发 5 路，HTTP/2 复用；当前位置附近片段临时提权
- 失败进重试队列并限并发重试；磁盘满先淘汰再写
- 会话编号防串片；进度持久化，重启后续下

### 阶段 4：稳态与终态
- 混合态 → 完成态（全本地，拖动毫秒级、断网可看）→ 下次秒开

### 无缝衔接技术
- **混合目录**：与原始目录逐行一致（数量/顺序/时长/断点标记），仅改片段地址
- **快照锁定**：对 FFmpeg 敏感内核，目录锁定为快照，每下载完一小批或全部完成时整体换新
- 广告剥离后双时间轴换算，见第 5 节

## 4. 严格缓存管理（本方案重点）

### 4.1 磁盘布局
```
<app支持目录>/jive_cache/
  index.json              # 元数据索引（唯一事实源，页面/统计只读它）
  <urlHash>/              # 每部影片/每集一个目录（hash = 剥 token 后 URL 的哈希）
    state.json            # url、标题、剧集名、总片段数、已下载数、字节数、lastAccess、complete、会话号
    manifest.m3u8         # 混合目录快照
    0000.ts … 0NNN.ts     # 片段文件
```

### 4.2 严格规则
1. **配额制**：默认 2GB（可配置）；每个片段写盘前检查配额，不足先淘汰再写，淘汰失败则跳过该片段、保持在线回退
2. **淘汰单元 = 整部**：按 lastAccess LRU 删整目录，优先删「已完成且最久未看」；**正在播放/下载中的会话绝不淘汰**（引用计数保护）
3. **索引先行**：展示与统计只读 `index.json`（毫秒级），app 启动校验一次 index vs 磁盘（文件数/大小），不一致自动重建
4. **会话编号防串片**：每次播放一个 UUID 会话，旧会话任务结果作废
5. **完整性校验**：片段落盘校验 size（对齐远端 Content-Length / TS 同步字节），失败标记重下
6. **清理并发安全**：删除前检查目标目录无活跃读/写（代理持有引用计数），避免删到正在吐片的片段
7. **手动清理双粒度**：全量清空 = 停下载器 → 会话全部作废 → 删 index+全部目录；单项删除 = 从 index 移除+删目录（若正播放先停该会话代理映射）

## 5. 广告过滤

识别哲学：**宁可漏过，不可误伤**。1 条明牌规则 + 6 层静态分析 + 1 层运行时 PTS 校验。

| 层 | 利用的规律 | 关键判据 | 防误伤机制 |
|---|---|---|---|
| 明牌规则 | 地址里写着 ad/adjump | 字符串匹配 | 只删明确标记的 |
| 1 帧率节奏 | 正片时长落在同一 fps 网格 | 主导网格 ≥90%；块内大量脱网且贴合异类网格；总长短 | 找不出主导网格就放弃；删除前整体复核 |
| 2 域名聚类 | 广告来自异域服务器 | 主导域名 >70%，删零星异域 | 占比不足整层放弃（防多 CDN 片源） |
| 3 序号跳变 | 广告文件名序号跳到别的数段 | 跳变 >1000；小段 <30 且不足最大段 1/3 | 80% 能解析出数字才启用 |
| 4 断点+时长 | 广告被断点包裹且片长短 | 宽 85% 中位数先合并，严 65% 再定罪 | 先宽后严两道闸 |
| 5 短片段聚类 | 广告是连续一长串短片段 | 连续 ≥5 段且均值 <50% 基准 | 阈值极严，宁漏勿错 |
| 6 结构侏儒块 | 广告是夹在巨人块间的小块 | ≤8 段、≤45 秒、两侧都是大块 | 首尾块豁免，保护片头片尾 |
| 7 PTS 校验 | 广告有独立时钟，正片会复位 | 跳变 ≥30 秒 + 复位误差 ≤2 秒 | 双重判据必须同时成立；基于真实流数据 |

**实施顺序**：先做明牌 + 静态六层（零/低成本），PTS 运行时校验作为独立后续项。

**双时间轴换算**：记录每条被剥广告在原始时间轴的位置和时长，切换时「新位置 = 原位置 − 之前广告累计时长」，保证进度条与剧情连续。

## 6. 「我的」页缓存管理

### 6.1 入口
`lib/features/profile_page.dart:36` 的 Card 内、「来源管理」下方新增 `ListTile`「缓存管理」，subtitle 实时显示 `已用 X MB / 共 N 部`，点击进入 `CacheManagementPage`。

### 6.2 页面 `lib/features/cache_management_page.dart`
- **顶部汇总卡**：总占用（人类可读）、缓存条目数、已用/配额进度条
- **操作**：`清理全部`（二次确认 AlertDialog，复用 `_HistoryTabState._clear` 的模式）、`刷新`（下拉重建索引）
- **条目列表**：每部影片一行（封面/标题/剧集/大小/完成度/最近观看时间），可**单项删除**
- 空态复用 `AppEmptyView`（无缓存时）

### 6.3 状态与数据流
- `lib/data/cache/cache_repository.dart`：`CacheManager`（配额/淘汰/引用计数/增删查）+ `cacheControllerProvider`（`AsyncNotifier<CacheStats>`，`ref.invalidate` 即刷新）
- `CacheStats`：`{ totalBytes, entryCount, quotaBytes, entries: [CacheEntry] }`
- `CacheEntry`：`{ title, urlHash, episode, bytes, complete, lastAccess, playable }`
- 播放器代理层写入片段时同步更新 index（每次落盘后 `state.json` 原子写或批量节流）
