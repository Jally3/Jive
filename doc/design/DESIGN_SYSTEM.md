# Jive App 视觉与交互规范

> 版本：V1.1 · 适用范围：Flutter Android / iOS MVP
>
> 本文档是前端实现和 UI 验收的单一视觉依据。除非产品决策明确变更，否则页面、组件和播放器不得自行引入新的颜色、字号、圆角或间距。

## 1. 产品主题定调

### 1.1 主题名称

**夜幕影院（Midnight Cinema）+ 暖昼（Warm Daylight）**

Jive 是一个轻量、直接、沉浸式的视频点播工具。普通页面支持日间与夜间模式：夜间以深色承托封面，日间使用低刺激暖白减少封面与背景的竞争；暖琥珀色始终负责行动引导，信息层级保持克制。播放画布和控制层在两种主题下均保持深色。

### 1.2 三个关键词

- **沉浸**：低干扰导航、播放画布和控制层固定深色并保持专注。
- **清晰**：封面优先，标题和更新信息清楚，状态反馈明确。
- **可靠**：加载、空数据、失败、重试和继续观看都使用统一表达。

### 1.3 明确不采用的方向

- 不使用高饱和霓虹、赛博朋克或游戏化装饰。
- 不使用大面积渐变、玻璃拟态、阴影堆叠和复杂动效。
- 不把首页做成信息流瀑布，不用过多徽章、角标和营销文案。
- 第一版不引入会员、社交、广告等视觉模块。

## 2. 视觉基础 Token

所有颜色必须集中定义在 `lib/app/theme.dart` 的 `AppPalette`，页面通过 Theme / `context.appColors` 使用语义颜色，禁止在页面 Widget 中直接写十六进制颜色。

### 2.1 颜色

| Token | 日间模式 | 夜间模式 | 用途 |
|---|---|---|---|
| `background` | `#F7F5F0` | `#0B0D10` | 页面主背景 |
| `surface` | `#FFFFFF` | `#13171C` | 卡片、底部栏、面板 |
| `elevated` | `#EFEAE1` | `#1B2027` | 弹层、次级表面、选中项 |
| `divider` | `#D8D1C5` | `#252B33` | 分割线、输入框边界 |
| `text` | `#1A1C1E` | `#F5F7FA` | 主标题、关键数据 |
| `secondary` | `#555C65` | `#A8B0BA` | 副标题、简介、辅助信息 |
| `tertiary` | `#747B84` | `#69737F` | 占位、时间、禁用信息 |
| `accent` | `#F2B84B` | `#F2B84B` | 主按钮、选中容器、播放进度 |
| `accentForeground` | `#8A5700` | `#F2B84B` | 普通背景上的强调文字、图标、边框 |
| `accentPressed` | `#D99A2B` | `#D99A2B` | 琥珀色容器按下态 |
| `onAccent` | `#17120A` | `#17120A` | 琥珀色背景上的文字和图标 |
| `success` | `#237A3B` | `#63C174` | 播放成功、可继续观看 |
| `error` | `#B3261E` | `#F06A6A` | 错误、失效、重试提示 |
| `scrim` | `#00000052` | `#00000099` | 图片或浮层遮罩 |

规则：

- 外观提供“跟随系统 / 日间模式 / 夜间模式”，默认跟随系统并持久化用户选择。
- 普通背景上的强调文字和图标必须使用 `accentForeground`；`accent` 用于实心容器和进度，不得在日间白色背景上作为小号正文色。
- 播放器画面、控制层和手势指示器固定使用深色播放器色板；竖屏信息区随应用主题切换。
- 主 CTA 使用 `accent`，每个视口最多一个最主要的实心 CTA。
- `accent` 只表示可操作或重要状态，不用于普通装饰。
- 正文和背景的对比度至少达到 WCAG AA；`textTertiary` 不承载必须阅读的信息。
- 图片加载失败时使用 `surfaceElevated` 占位，不显示破图图标或白色背景。

### 2.2 字体与字号

优先使用系统字体，保证中英文和数字在 Android / iOS 上稳定显示：

- iOS：`SF Pro Display` / `PingFang SC`
- Android：`Roboto` / `Noto Sans CJK SC`

| Token | 字号 / 行高 | 字重 | 用途 |
|---|---:|---:|---|
| `display` | 28 / 36 | 700 | 页面主标题、详情标题 |
| `headline` | 22 / 30 | 700 | 重点区块标题 |
| `title` | 17 / 24 | 600 | 卡片标题、导航标题 |
| `body` | 15 / 22 | 400 | 正文、简介 |
| `label` | 13 / 18 | 500 | 分类、按钮、辅助标签 |
| `caption` | 12 / 16 | 400 | 更新时间、集数、次要说明 |

规则：

- 标题最多显示两行，超出使用省略号。
- 正文默认左对齐；数字、时间和集数保持清晰，不使用过细字重。
- 按钮文字使用 `label`，禁止全大写。

### 2.3 间距、圆角与尺寸

采用 4pt 基础网格，仅使用以下间距：`4 / 8 / 12 / 16 / 20 / 24 / 32`。

| Token | 值 | 用途 |
|---|---:|---|
| `pagePadding` | 16 | 页面左右边距 |
| `sectionGap` | 24 | 区块之间 |
| `itemGap` | 12 | 卡片或列表项之间 |
| `contentGap` | 8 | 标题、元信息之间 |
| `cardRadius` | 12 | 视频卡片、图片 |
| `controlRadius` | 10 | 输入框、按钮、Chip |
| `pillRadius` | 999 | 胶囊标签 |
| `tapTarget` | 44 | 最小可点击区域 |

- 页面内容不得贴边；横向安全区默认 16pt，平板或大屏仍保持合理最大宽度。
- 卡片不使用粗边框；以背景层级和 12pt 圆角区分。
- 阴影仅用于弹层，且保持低透明度；普通卡片不使用浮夸阴影。

## 3. 组件规范

### 3.1 App Bar 与导航

- 页面顶部使用透明或 `background` 背景，不使用高耸的彩色头图。
- 标题使用 `title`，左对齐；返回按钮和右侧操作均保持 44pt 点击区域。
- 底部导航固定 3 个入口：**首页、搜索、我的**。
- 当前入口使用 `accent` 图标和文字，未选中使用 `textTertiary`；不使用彩色圆底大按钮。
- 播放页隐藏底部导航，详情页保留返回路径。

### 3.2 视频卡片

卡片是全局最重要的内容组件，统一使用 `VideoCard` / `VideoGrid`。

- 封面比例固定为 **2:3**；使用 `BoxFit.cover`，不拉伸。
- 封面圆角 12pt；底部可叠加从透明到 `scrim` 的轻遮罩。
- 标题最多两行，使用 `title`；标题下显示类型或更新状态，使用 `caption`。
- `vod_remarks` 优先作为更新/集数信息；缺失时不渲染空标签。
- 继续观看时在封面底部显示 3pt `accent` 进度条，不叠加大面积“继续播放”文字。
- 网格列数由屏幕宽度决定：手机竖屏 2 列，横屏可 3–4 列；卡片间距 12pt。

### 3.3 分类 Chip

- 未选中：`surfaceElevated` 背景、`textSecondary` 文字。
- 选中：`accent` 背景、`onAccent` 文字。
- 高度 36pt，左右内边距 12pt，圆角使用 `pillRadius`。
- 横向滚动时首尾保留 16pt 内边距，不自动换行成密集墙面。

### 3.4 搜索框

- 背景使用 `surface`，边框使用 `divider`；聚焦时边框切换为 `accent`。
- 高度 48pt，圆角 10pt；左侧搜索图标，右侧仅在有文本时显示清除按钮。
- 搜索页输入后使用防抖；等待请求时在结果区域显示轻量加载，不替换整个页面。
- 无结果文案应提供下一步，例如“换个关键词试试”，并保留搜索框可编辑。

### 3.5 按钮与操作

- 主按钮：`accent` 背景 + `onAccent` 文字，圆角 10pt，高度 48pt。
- 次按钮：透明背景 + `divider` 边框 + `textPrimary` 文字，高度 44pt。
- 文本按钮：无背景，使用 `accent`，只用于次要操作。
- 播放按钮为圆形主操作，最小 52pt；详情页中只能有一个视觉最强的播放入口。
- 禁用态降低透明度，不使用灰色大面积覆盖；加载态保留按钮尺寸，避免布局跳动。

### 3.6 加载、空数据和错误

三种状态必须使用统一的 `AppLoadingView`、`AppEmptyView`、`AppErrorView`，不得每个页面自定义一套。

- 初次加载：骨架屏优先，骨架使用 `surface` / `surfaceElevated`，不使用旋转指示器占满页面。
- 分页加载：列表底部显示小型加载指示器，不遮挡已有内容。
- 空数据：简洁图标 + 一句说明 + 可选行动按钮，垂直居中但不铺满插画。
- 错误：说明“发生了什么”并提供“重试”；网络失败不使用责备用户的语气。
- 所有状态均支持安全区、日间/夜间背景和无障碍朗读。

### 3.7 全局提示 Toast

所有轻量反馈统一使用 `showAppToast`（`lib/shared/app_toast.dart`），不再使用底部 SnackBar。

- 位置：屏幕水平、垂直居中；最大宽度为屏宽 70% 与 360pt 的较小值，文本最多两行省略。
- 样式：`surfaceElevated` 背景 + `divider` 1pt 描边 + 12pt 圆角 + 轻微阴影；文字 `textPrimary` 13pt/500；可选操作按钮使用 `accent` 文字。
- 行为：停留 2 秒后自动消失，进入 200ms / 退出 150ms ease-out 淡入淡出；同时只显示一条，新提示替换旧提示。
- 无操作按钮时指针事件穿透，不得拦截下层手势（尤其是播放器控制层）。

## 4. 页面定调

### 首页

结构：顶部标题 → 分类 Chip 行（`最新` + 分类接口返回的全部根分类）→ 分页网格。

首页第一屏优先展示可播放内容，不使用大型营销 Banner。区块标题使用 `headline`，右侧“查看更多”使用 `label` + `accent`。如果没有推荐算法，文案统一使用“最新内容”，不伪装成个性化推荐。点选分类 Chip 时保留页面结构，使用局部加载和淡入，不整页闪烁。

### 搜索页

进入页面即聚焦搜索框。未搜索时显示简短引导；搜索后标题显示“搜索结果”，结果数量不是必须信息。搜索结果和首页卡片使用同一 `VideoCard`，不创建第二种卡片样式。

### 详情页

上部使用封面 + 遮罩信息，下部为标题、类型、更新状态、简介、剧集列表。首屏必须能看到主播放按钮。简介默认最多展示 4 行，提供展开/收起。剧集采用紧凑网格或列表，当前剧集使用 `accent` 边框/文字标识。

### 播放页

视频画布、播放控制层和横屏/全屏区域固定使用黑色沉浸式样式；竖屏下的标题栏、简介、跳过设置和选集面板跟随当前应用主题。横屏全屏时隐藏非必要信息。控制层采用 `scrim`，控件使用白色，进度条使用 `accent`。控制层自动隐藏；点击画面显示/隐藏控制层。错误时保留播放器上下文，显示重试和返回，不直接跳转到空白页面。

### 我的

「收藏」与「最近观看」两个 Tab 合并入口。收藏复用视频卡片网格；最近观看按观看时间倒序排列，卡片额外显示“已观看进度 / 继续播放”。无记录时使用统一空状态，不显示与会员或登录相关的引导。

## 5. 动效与反馈

- 页面/区块切换：180–240ms，使用标准 ease-out。
- 按钮按下反馈：100–150ms，轻微透明度变化即可。
- 图片加载完成可淡入 160ms；禁止大幅缩放和视差。
- 播放器控制层显示/隐藏 200ms；拖动进度时必须优先保证响应速度。
- 尊重系统“减少动态效果”设置；关闭动效后不得影响功能。

## 6. Flutter 落地约束

建议文件对应关系：

```text
lib/app/theme.dart                  # AppPalette、双 ThemeData、组件主题
lib/data/theme_mode_preferences.dart # 主题选择持久化与 Riverpod 状态
lib/shared/widgets/video_card.dart  # 全局卡片
lib/core/widgets/                   # 加载、空数据、错误状态
```

实施要求：

- 页面只消费 Theme / Token，不直接定义视觉常量。
- 所有可点击元素满足至少 44 × 44pt。
- 所有图片、按钮、Chip 和状态组件优先复用 shared 组件。
- 新增组件前先确认是否可以扩展现有组件；不得因单页需求复制一套相似样式。
- 视觉验收重点：颜色 Token、字号层级、卡片比例、间距网格、状态完整性、横竖屏播放器体验。

## 7. 设计验收清单

- [ ] 全部普通页面同时通过日间、夜间主题和规定 Token 验收。
- [ ] 跟随系统、手动日间、手动夜间均能即时切换并在重启后保持。
- [ ] 播放器在两种应用主题下均保持深色画布和控制层，竖屏信息区跟随应用主题。
- [ ] 首页、搜索、我的（收藏/最近观看）的卡片视觉完全一致。
- [ ] 详情页首屏存在清晰主播放入口。
- [ ] 加载、空数据、失败、重试均有统一组件。
- [ ] 播放页横竖屏、暂停、拖动、退出和失败状态不破坏布局。
- [ ] 无封面、无简介、无剧集、过期地址等异常数据有可理解反馈。
- [ ] 文字支持中英文，长标题不会溢出。
- [ ] 关键文字与背景满足可读性要求，点击目标不小于 44pt。
- [ ] 没有未经批准的新颜色、渐变、字体、圆角或阴影。
