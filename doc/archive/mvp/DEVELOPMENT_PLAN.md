# 视频 App 第一版开发周期规划

## 1. 规划依据

本计划基于：

- `APP_REQUIREMENTS_V1.md`
- `ARCHITECTURE.md`
- 当前 VOD 源：暴风资源 API

## 2. 开发策略

第一版采用“两阶段策略”：

1. **先不部署后端**，直接接入 VOD 源，快速验证列表、详情、剧集解析和视频播放闭环。
2. **保留 Repository 和 Source Adapter 抽象**，后续可以平滑切换到自有后端和多 VOD 源架构。

第一版目标不是立即完成完整商业产品，而是先得到一个 Android 和 iOS 真机可运行的 MVP。

## 3. 建议周期总览

建议总周期：约 6 周。

| 阶段 | 周期 | 主要目标 |
|---|---:|---|
| 阶段 0 | 0.5 周 | 项目初始化和技术验证 |
| 阶段 1 | 1 周 | VOD 源接入和播放器闭环 |
| 阶段 2 | 1.5 周 | 首页、分类和搜索 |
| 阶段 3 | 1 周 | 详情、剧集和播放体验 |
| 阶段 4 | 0.5 周 | 最近观看和播放进度 |
| 阶段 5 | 1 周 | 异常、弱网和真机测试 |
| 阶段 6 | 0.5 周 | 打包、文档和后端演进准备 |

实际周期会受 VOD 源稳定性、视频播放格式、个人投入时间和 UI 复杂度影响。

## 4. 阶段 0：项目初始化和技术验证

### 时间

第 1 周前半段，约 2～3 天。

### 工作内容

- 创建 Flutter Android/iOS 项目。
- 配置开发、测试和生产环境变量。
- 建立 Feature-first 目录结构。
- 接入 Riverpod、Dio、路由和视频播放器依赖。
- 确认 Android 和 iOS 最低支持版本。
- 准备 Android 真机和 iPhone 真机。
- 选取一个真实 `vod_id`。
- 请求暴风资源详情接口。
- 确认 `vod_play_url` 的实际结构。

### 交付物

- 项目可以在 Android 和 iOS 启动。
- 网络请求和 JSON 解析样例。
- 一份真实详情接口响应样本。
- 播放地址解析规则说明。

### 通过标准

- 确认至少一个视频存在可播放地址。
- 确认地址格式为 `.m3u8`、DASH 或可支持的 MP4。
- 确认 Android 和 iOS 播放能力可行。

> 如果这一阶段无法得到合法且稳定的实际播放地址，应暂停 UI 开发，先解决数据源问题。

## 5. 阶段 1：VOD 源接入和播放闭环

### 时间

第 1 周后半段至第 2 周前半段，约 5 天。

### 工作内容

- 实现 `StormApiClient`。
- 实现列表、分类、搜索和详情请求。
- 实现 `StormParser`。
- 解析视频、分类、剧集和播放地址。
- 建立统一的 `Video`、`VideoDetail`、`Episode`、`PlaySource` 模型。
- 实现 `VideoRepository` 和 `PlayerRepository`。
- 完成详情页点击剧集进入播放页。
- 初始化、暂停、恢复和销毁播放器。

### 交付物

- `StormAdapter` 或等价的暴风资源 DataSource。
- 详情页到播放页的完整链路。
- 可播放的最小播放器页面。

### 通过标准

```text
视频列表 → 视频详情 → 选择剧集 → 获取播放地址 → 播放
```

在 Android 和 iOS 真机各成功播放至少一个视频。

## 6. 阶段 2：首页、分类和搜索

### 时间

第 2 周后半段至第 4 周前半段，约 7～8 天。

### 工作内容

#### 首页

- 视频列表。
- 封面、标题、分类和更新状态。
- 下拉刷新。
- 分页加载。
- 加载中、空数据、失败和重试状态。

#### 分类

- 分类列表。
- 分类视频列表。
- 分类分页。
- 分类切换后的状态刷新。

#### 搜索

- 搜索输入框。
- 300～500ms 防抖。
- 取消上一次请求。
- 搜索结果分页。
- 空关键词和无结果处理。

### 交付物

- 首页。
- 分类页。
- 搜索页。
- 统一的列表组件和错误状态组件。

### 通过标准

- 首页、分类和搜索均能展示真实数据。
- 连续翻页不会重复或错乱。
- 快速输入关键词不会造成旧请求覆盖新结果。
- 无网络或接口异常时页面可恢复。

## 7. 阶段 3：详情、剧集和播放体验

### 时间

第 4 周，约 5 天。

### 工作内容

- 完善视频详情页。
- 展示封面、简介、类型、状态和更新时间。
- 展示剧集列表。
- 记录当前剧集。
- 支持播放、暂停和进度拖动。
- 支持全屏和横竖屏切换。
- 处理播放地址过期和重新获取。
- 处理播放器初始化失败。
- 处理 App 进入后台和返回前台。
- 播放页销毁时释放播放器资源。

### 交付物

- 完整详情页。
- 可用的剧集选择器。
- 稳定的播放页。

### 通过标准

- 电影和连续剧均能正确播放。
- 可以切换不同剧集。
- 播放失败时显示原因和重试入口。
- 连续进入和退出播放页没有明显卡顿或资源泄漏。

## 8. 阶段 4：最近观看和播放进度

### 时间

第 5 周前半段，约 3 天。

### 工作内容

- 建立 `WatchHistoryRepository`。
- 使用本地存储保存最近观看。
- 保存视频、剧集、播放位置和总时长。
- 每 5～10 秒保存一次进度。
- 暂停时保存。
- 退出播放器时保存。
- 播放完成时标记完成。
- 从最近观看继续播放。
- 限制最近记录数量。

### 交付物

- 最近观看页面。
- 播放进度恢复功能。
- 本地数据清理能力。

### 通过标准

- 退出 App 后记录仍然存在。
- 再次打开可以恢复到上次播放位置。
- 播放完成的视频不会出现错误的负数或超长进度。

## 9. 阶段 5：稳定性和真机测试

### 时间

第 5 周后半段至第 6 周前半段，约 5 天。

### 测试范围

#### 网络

- 正常 Wi-Fi。
- 移动网络。
- 弱网。
- 断网后恢复。
- API 超时。
- 播放地址过期。

#### 播放器

- 播放、暂停、拖动。
- 横竖屏切换。
- 锁屏和后台切换。
- 来电或耳机插拔。
- 快速退出和重新进入。
- 连续播放多集。

#### 数据异常

- 缺少封面。
- 缺少简介。
- 无剧集。
- 空播放地址。
- 非预期分隔符。
- 重复剧集。
- 非法 JSON 或字段类型错误。

#### 设备

- 一台低端 Android 设备。
- 一台主流 Android 设备。
- 一台 iPhone 真机。
- 不同屏幕尺寸。

### 交付物

- 测试记录。
- 已知问题清单。
- 崩溃和播放错误日志。
- 发布候选版本。

### 通过标准

- 核心流程没有阻塞性问题。
- 网络和播放异常不会导致 App 崩溃。
- 播放器资源能正确释放。
- Android 和 iOS 都能完成核心验收流程。

### 交付物

- iOS 测试包。

## 13. 进入后端开发的触发条件

满足以下任一条件时，开始设计并实现自有后端：

- 需要接入第二个 VOD 源。
- 需要登录、会员、支付或权限控制。
- 需要隐藏源 API 或播放地址规则。
- 需要统一缓存、搜索、去重和故障切换。
- 需要正式商业上线。
- 当前源稳定性无法满足客户端要求。

后端迁移顺序：

```text
Flutter 保留 Repository 接口
  ↓
新增 OwnBackendDataSource
  ↓
后端实现 StormAdapter
  ↓
将列表、详情和播放请求切换到 /api/v1
  ↓
保留本地播放和观看记录逻辑
```

## 14. 第一版完成定义

当以下条件全部满足时，第一版视为完成：

- Android 和 iOS 真机可以启动。
- 首页、分类、搜索和详情可以加载真实数据。
- 至少一个视频和一个连续剧剧集可以播放。
- 播放器支持暂停、拖动、全屏和退出释放。
- 播放错误、网络错误和空数据有明确提示。
- 最近观看和播放进度可以保存和恢复。
- 核心流程通过弱网、断网和地址失效测试。
- 当前 VOD 源的内容和播放权限已经完成合规确认。
- 项目代码保留向自有后端和多 VOD 源迁移的接口边界。
